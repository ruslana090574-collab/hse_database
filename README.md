## Сборка из исходников (для проверки, не обязательна студенту)

Требуется установленный LibreOffice с Base/Firebird и Python с модулем `uno`, JDK для Report Builder, Python-пакеты из `requirements-build.txt`, Graphviz `dot`. Скрипты разрешают пути относительно репозитория, кроме стандартного локального UNO-порта 2002.

Запустите LibreOffice с `--accept='socket,host=127.0.0.1,port=2002;urp;StarOffice.ComponentContext' --norestore --nodefault`. На macOS исполняемый файл обычно находится в `/Applications/LibreOffice.app/Contents/MacOS/soffice`.

В каталоге проекта, в новой копии без готового ODB, выполните последовательно Python с UNO: `scripts/build_database.py`, `scripts/build_forms.py`, `scripts/finish_forms.py`, `scripts/build_reports.py`, `scripts/export_results.py`, `scripts/build_mailmerge.py`. Для Calc сначала обычным Python выполните `scripts/build_spreadsheet.py`, затем Python с UNO — `scripts/link_spreadsheet.py`. Проверка — `scripts/validate_database.py`. Для схем нужен `scripts/build_diagrams.py`, для отчёта — `scripts/build_documents.py` после получения иллюстраций.

Не перезаписывайте существующую базу и результаты слияния: скрипты сборки базы и слияния останавливаются при их наличии. Сохраните их отдельно перед повторной сборкой. Скриншоты — реальные окна Base/Calc; иллюстрации отчёта и полиса — страницы фактического PDF-экспорта. Папка `deliverables` не включается в сам архив.

`sql/schema.sql` использует `SET TERM` для Firebird isql. Не вставляйте его целиком в окно SQL Base: команда SET TERM относится к isql. UNO-сборка использует уже разделённые операторы из модели/`schema.json`. `query_overrides.json` содержит окончательные совместимые определения запросов, `service_choices.json` — SQL вспомогательного представления.
